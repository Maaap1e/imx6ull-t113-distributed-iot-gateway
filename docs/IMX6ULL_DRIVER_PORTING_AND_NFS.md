# i.MX6ULL 驱动适配与 NFS 调试记录

## 范围说明

AP3216C（I2C）和 ICM20608（SPI）驱动工作基于 i.MX6ULL 官方或开发板例程完成，重点是板级设备树适配、寄存器与字符设备数据通路修改、用户态验证和联调效率，而不是重新实现 Linux I2C/SPI 核心框架。

完整内核和板级 BSP 当前未整体放入本仓库。原因是体积较大，并且包含厂商与开发板代码；公开时应优先提交自己修改过的最小补丁，而不是复制整个源码树。

## 实际调试链路

```text
Ubuntu 虚拟机
    -> 修改驱动与设备树
    -> 使用 i.MX6ULL 交叉工具链构建
    -> NFS 共享目录
    -> 开发板挂载并加载模块/运行测试程序
    -> dmesg + /dev + 用户态读数验证
```

### 1. 设备树适配

检查并按实际原理图修改：

- 控制器是否启用；
- `compatible` 与驱动匹配表是否一致；
- I2C 地址或 SPI 片选是否正确；
- SPI 最大频率、工作模式及 pinctrl 是否符合板级连接；
- 节点 `status` 是否为 `okay`。

验证时依次确认设备树被加载、总线设备被枚举、驱动 `probe` 成功。若没有进入 `probe`，先检查匹配和总线层，不直接在 `read` 路径中盲目调试。

### 2. 驱动数据通路

驱动侧重点包括：

- 初始化传感器并读取芯片 ID 或关键状态寄存器；
- 封装 I2C/SPI 寄存器读写；
- 注册字符设备并实现必要的 `open`、`read`、`release` 等接口；
- 对用户缓冲区长度、设备未就绪和总线读写失败进行检查；
- 在 `remove` 或错误路径中按相反顺序释放资源。

用户态网关同时保留传感器失败隔离逻辑，单个设备读取失败不会阻断 CAN 状态汇聚和 TCP 发送。相关入口见 [`linux/imx6ull_gateway/sensors.c`](../linux/imx6ull_gateway/sensors.c)。

### 3. NFS 挂载调试

Ubuntu 虚拟机将构建产物目录导出为 NFS 共享。下面命令使用占位地址，实际执行时替换为虚拟机 IP 和真实目录：

```sh
# Ubuntu：示例导出目录
sudo exportfs -v

# i.MX6ULL：创建挂载点并挂载共享目录
mkdir -p /mnt/nfs
mount -t nfs -o nolock,vers=3 \
    <VM_IP>:/path/to/imx6ull-build-output /mnt/nfs

# 确认开发板可以看到最新产物
ls -lh /mnt/nfs
```

根据驱动的构建方式加载模块或更新镜像。模块方式可在卸载旧版本后加载新产物：

```sh
rmmod <old_module> 2>/dev/null || true
insmod /mnt/nfs/<new_module>.ko
dmesg | tail -n 50
ls -l /dev/<device>
```

随后直接从 NFS 目录运行用户态测试程序，避免每次修改都重新复制文件：

```sh
chmod +x /mnt/nfs/<sensor_test_app>
/mnt/nfs/<sensor_test_app>
```

NFS 只用于开发调试。正式运行时，驱动、设备树和应用应进入可复现的内核/BSP构建或版本化安装包，不依赖开发机在线。

## 分层排查顺序

1. **设备树层**：确认当前 DTB、节点状态、`compatible`、地址/片选和 pinctrl。
2. **总线层**：确认 I2C/SPI 控制器及目标设备被枚举，没有持续的传输错误。
3. **驱动层**：检查 `probe`、芯片 ID、资源申请和字符设备注册日志。
4. **设备节点层**：确认 `/dev` 节点存在、权限正确、主次设备号匹配。
5. **用户态层**：使用最小测试程序读取原始值，再接入网关服务，避免把 UI 或网络问题误判为驱动问题。
6. **系统集成层**：确认传感器异常时网关仍能处理 CAN、维护状态文件并继续重连 T113。

## 建议补充到仓库的最小证据

在确认板厂代码许可允许后，后续可新增下列小文件，而不是提交完整 BSP：

- 仅包含自定义节点的 DTS/DTSI 补丁；
- AP3216C、ICM20608 驱动相对基线例程的补丁；
- 用户态测试程序与一份成功的 `dmesg`/读数记录；
- 交叉编译命令、内核版本和开发板型号；
- NFS 挂载与一次完整验证的终端记录。

这些证据可以让阅读者区分“完成过驱动适配”和“仓库中可独立复现的驱动代码”，避免对贡献范围产生误解。
